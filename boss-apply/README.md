# boss-apply — BOSS直聘求职全自动流水线

> 一句话：你告诉它「投什么岗位、投哪个城市」，它负责抓岗位、打分、建看板、每天自动打招呼投递，边投边自动补新岗位、清掉下架的，全程有记录可查。

## 这是什么

这是一套跑在你自己电脑上的求职自动化工具，对接 **BOSS直聘**（zhipin.com），一共干四件事：

1. **抓岗位** —— 按你配的关键词和城市，自动翻 BOSS 搜索页，把职位（标题/薪资/公司/技能标签/链接）抓成结构化数据
2. **打分级** —— 给每个岗位算匹配分（Agent/大模型/薪资/公司规模加权），分成 S / A / B 三档
3. **生成看板** —— 产出一个本地 HTML 看板（拖拽式五列：待投递→已投递→沟通笔试→面试中→结束），双击就能开，不需要装任何服务
4. **自动投递** —— 逐个打开职位页，点「立即沟通」、确认问候语、有机会时点「发送简历」，然后重开页面验证真的投上了才记成功；投的同时定期抓新岗位补充队列，下架的自动清掉

它**不是**：群发广告的营销工具、简历代写工具、也不碰你的账号密码（登录用的是你自己扫码后的会话）。

## 给谁用

**适合你，如果：**

- 你在用 BOSS直聘找工作，每天要手动点几十个「立即沟通」，重复到麻木
- 你想海投但有分寸：限定城市、限定岗位方向、限定每日上限，B 档烂岗位自动不投
- 你想要一个总览面板：投了哪些、哪些没投、哪些下架了，一目了然
- 你会开终端、会改一个 JSON 配置文件（仅此而已，不需要会编程）

**不适合你，如果：**

- 你指望它自动写简历、自动面试（不做这个）
- 你完全不能接受任何账号风险（见文末「风险与安全」，虽然做了大量拟人化防护，但自动化操作 BOSS 账号本身有被限制的可能，介意慎用）
- 你想让它在服务器上 24 小时跑（它要弹出一个真实的 Chrome 窗口，需要有人偶尔处理滑块验证，适合挂在自己电脑上白天跑）

## 四个核心功能详解

### ① 抓岗位（scrape）

你说「AI产品经理，上海+杭州+深圳」，它就逐个城市逐个关键词打开 BOSS 搜索页，往下滚动，**拦截搜索接口返回的数据**（不是解析网页，稳定得多），去重、过滤掉不相关和黑名单岗位（纯开发/销售/客服等），按评分排好序存进 `jobs.json`。

- 一次全量抓：每个「关键词×城市」组合滚到 60 条左右
- 日常增量抓：每次只抓每个组合的第 1 页，专收新发布的岗位
- 城市码填错了也不会污染数据——抓回来会按 BOSS 返回的城市名自校验

### ② 打分级（自动）

透明可解释的打分，不是黑盒：

```
底分 8
+ 关键词命中：Agent/智能体/大模型 +2，RAG/多模态/语音 +1.5 …（封顶 +6）
+ 薪资：月均 ≥25K +3，≥20K +2，≥15K +1，<12K -1
+ 公司千人以上 +1
= 总分（5~18）
```

**S 档 ≥11、A 档 8-10 进投递队列；B 档只上板不投**——海投也有底线。

### ③ 生成看板（board）

从 `jobs.json` 生成一个单文件 HTML 看板：五列拖拽、S/A/B 彩色标档、匹配分、薪资、时间戳，右上角有「导入投递」按钮（把自动投递的结果同步进列位，只前进不降级）。纯本地文件，发给谁都能打开。

### ④ 自动投递（auto —— 日常主命令）

每条岗位的完整动作：

```
打开职位详情页 → 判断状态（下架/要登录/有验证码/正常）
→ 模拟真人滑动浏览 → 找「立即沟通」按钮
   （按钮已是「继续沟通」= 投过，跳过不重复投）
→ 点击 → 聊天窗自动确认问候语 → 出现「发送简历」就点
→ 重开职位页验证按钮真的变成「继续沟通」才算成功
→ 记录到 progress.json，等 18~45 秒再投下一条
```

投递过程中每隔 5 条（或 12 分钟）**自动回头抓一轮新岗位**补充队列——这就是「边投边补」，队列永远不断粮。跑完自动把下架岗位从看板清掉、生成看板同步文件。

## 怎么做：手把手场景指南

### 场景 A：第一次用，从零到投出第一份（约 10 分钟）

```bash
cd C:\Users\Admin\.claude\skills\boss-apply

# 第 1 步：装依赖（只需一次）
pip install DrissionPage==4.1.1.4

# 第 2 步：生成默认配置
python apply_boss.py init
```

第 2 步会生成 `~/.boss-apply/config.json`，**打开它改这四组**（默认值是 AI 产品经理方向，换方向必须全改，缺一个抓回来的都是别的方向岗位或直接被过滤光）：

```jsonc
{
  // ① 搜索关键词：想投什么岗位就写什么
  "keywords": ["AI产品经理", "AI Agent"],

  // ② 目标城市：格式必须是 {"城市名": "BOSS城市码"}，城市名要写对（用于校验）
  "cities": {"北京": "101010100", "上海": "101020100"},

  // ③ 相关性过滤：岗位必须「标题/技能含 must_have 任一词」且「含 role 任一词」，
  //    标题命中 blacklist 任一词直接丢弃。换方向时这三个列表都要换成新领域的词
  "filter": {
    "must_have": ["AI", "大模型", "LLM"],
    "role": ["产品", "PM"],
    "blacklist": ["开发", "测试", "销售"]
  },

  // ④ 评分加分词：决定 S/A/B 档位（S≥11, A≥8, B<8）。换方向时换成新领域词，
  //    不改的话新方向的岗位大多只能评 A，配合下面 priorities:["S","A"] 也能投，但排序变差
  "score_hints": {"大模型": 2.0, "llm": 2.0},

  "priorities": ["S", "A"],                  // 投递档位
  "daily_cap": 25                            // 每天最多投几条，建议 ≤30
}
```

改完先跑 `python apply_boss.py doctor`，它会明确告诉你关键词/城市是否已生效、还是仍在用内置默认。

```bash
# 第 3 步：全量抓岗位（会弹出 Chrome 自动翻页，几分钟）
python apply_boss.py scrape

# 第 4 步：登录校验 + 生成看板
python apply_boss.py doctor    # 弹出 Chrome，若提示未登录则用手机扫码
python apply_boss.py board     # 桌面出现「BOSS投递看板.html」，双击打开看一眼

# 第 5 步：先干跑确认没坑（不真投，只打印会投哪些）
python apply_boss.py auto --dry-run

# 第 6 步：真投（弹出 Chrome 自动操作；如遇滑块验证，你手动滑一下即可）
python apply_boss.py auto --limit 5
```

看到 `[N/M] 公司名 · 职位名` 就是在投了，投完一条会打印 `applied`/`already_contacted` 等结果。中途想停？在另一个终端 `python apply_boss.py stop`（或建文件 `~/.boss-apply/STOP`），它投完当前这条就收工，**不要直接杀进程**。

### 场景 B：每天日常（一条命令）

```bash
python apply_boss.py auto
```

它自己会：验证登录 → 取 S/A 档未投队列 → 逐条投递 → 边投边补新岗 → 达到每日上限自动停 → 清下架岗位 → 生成看板同步文件。你只需要偶尔瞄一眼 Chrome 窗口有没有滑块。

### 场景 C：换岗位方向 / 换城市

**只改 `keywords`/`cities` 不够**——`filter`（must_have/role/blacklist）和 `score_hints` 也是按方向写死的默认值，不改的话新方向岗位会被当「不相关」过滤光。四组一起改：

```jsonc
// 例：换成「跨境电商运营」方向
"keywords": ["跨境电商运营", "亚马逊运营"],
"cities": {"深圳": "101280600", "广州": "101280100"},
"filter": {
  "must_have": ["电商", "跨境", "亚马逊", "Shopify", "独立站"],
  "role": ["运营", "推广"],
  "blacklist": ["开发", "测试", "客服"]
},
"score_hints": {"亚马逊": 2.0, "独立站": 1.5, "shopify": 1.5, "选品": 1.0}
```

然后：

```bash
python apply_boss.py doctor    # 确认配置已生效（缺项会红字警告）
python apply_boss.py scrape    # 重新全量抓
python apply_boss.py board     # 重新生成看板（已有投递记录不受影响）
```

已投过的岗位不管怎么换配置都不会重复投（记录在 `~/.boss-apply/progress.json`）。

### 场景 D：只想补新岗位，先不投

```bash
python apply_boss.py refresh   # 增量抓每个关键词的第一页，新岗位标 src:"r" 排队列最前
python apply_boss.py board
```

看完板子觉得岗位质量 OK，再跑 `auto`。

### 场景 E：查「为什么这条没投 / 投到哪一步了」

```bash
python apply_boss.py status            # 今日进度、队列情况、最近一次运行状态
python apply_boss.py export            # 强制把 progress 同步进看板
```

每个岗位的处理结果都记在 `~/.boss-apply/progress.json`（`st` 字段）和 `run-log.jsonl`（逐条流水），看板里也会显示。

## 命令一览

| 命令 | 干什么 | 会弹 Chrome 吗 |
|---|---|---|
| `init` | 生成默认配置到 `~/.boss-apply/config.json` | 否 |
| `scrape` | 全量抓岗位：每个关键词×城市滚 ~60 条，评分入库 | 是 |
| `refresh` | 增量抓新岗：每组合只抓第 1 页，新岗排最前 | 是 |
| `board` | 生成/更新桌面看板 HTML | 否 |
| `doctor` | 检查登录态，未登录则引导扫码 | 是 |
| `auto` | 主命令：自动投递 + 边投边补 + 清下架 + 同步看板 | 是 |
| `auto --dry-run` | 干跑：只打印将投哪些，不真投 | 是 |
| `auto --limit N` | 本次最多真投 N 条 | 是 |
| `status` | 看今日进度 / 队列 / 最近运行状态 | 否 |
| `export` | 把投递记录强制同步进看板 | 否 |
| `stop` | 建立停止标记，auto 投完当前这条后优雅退出 | 否 |

## 配置详解（`~/.boss-apply/config.json`）

```jsonc
{
  "keywords": ["AI产品经理", "AI Agent"],     // 搜索关键词，可多个
  "cities":   {"杭州": "101210100"},          // {"城市名": "BOSS城市码"}，城市名参与校验必须写对
  "filter": {                                 // 相关性过滤（换方向必须改）
    "must_have": ["AI", "大模型"],             // 标题/技能须命中任一词
    "role": ["产品", "PM"],                    // 且须命中任一词
    "blacklist": ["销售", "客服"]              // 标题命中任一词直接丢弃
  },
  "score_hints": {"大模型": 2.0, "rag": 1.5}, // 评分加分词（S≥11, A≥8, B<8），换方向建议改
  "priorities": ["S", "A"],                   // 只有这些档位会进投递队列
  "daily_cap": 25,                            // 每日真投上限（已投的不重复计）
  "min_delay_s": 18, "max_delay_s": 45,       // 两条投递间的随机停顿区间（防风控）
  "max_run_minutes": 45,                      // auto 单次最长运行时间
  "captcha_wait_s": 300,                      // 出现滑块时等你手动的最长时间
  "auto_send_resume": true,                   // 聊天窗出现「发送简历」按钮时是否自动点
  "profile_dir": "C:\Users\Admin\.boss-zhipin-scraper\chrome-profile",  // Chrome 登录态存这里
  "chrome_port": 9222,
  "board_html": "C:\Users\Admin\Desktop\BOSS投递看板.html",
  "refresh": {                                // 「边投边补」节奏
    "every_n_applies": 5,      // 每投 5 条触发一轮增量抓
    "every_m_minutes": 12,     // 或每 12 分钟触发一轮
    "max_new_per_round": 10,   // 单轮最多补 10 条
    "max_new_per_run": 30      // 单次 auto 最多补 30 条
  }
}
```

## 投递状态判定（progress.json 里的 `st`）

| 状态 | 含义 | 占用今日额度吗 |
|---|---|---|
| `applied` | 重开页面确认按钮已变「继续沟通」，真投上了 | ✅ |
| `already_contacted` | 打开就是「继续沟通」，之前投过（含你手动的），跳过 | ❌ |
| `offline` | 岗位已下架 | ❌ |
| `limit_hit` | 系统提示已达沟通上限（如未回消息数超限） | ❌ |
| `need_login` | 会话失效，重新 `doctor` 扫码 | ❌ |
| `captcha` | 出滑块你没来得及滑，超时退出 | ❌ |
| `unknown` | 页面状态认不出，存截图到 `screenshots/` 供排查 | ❌ |

## 排障

| 现象 | 原因 / 解决 |
|---|---|
| `登录状态已失效` | `python apply_boss.py doctor` 重新扫码 |
| 投递时卡在滑块 | Chrome 窗口里手动滑，300 秒内滑完继续 |
| 全是 `unknown` | 看 `screenshots/` 截图；多半是 BOSS 改版，改 `selectors` |
| 抓回来 0 条 | 关键词太冷门或城市码错；先用全国码 `100010000` 试 |
| 看板岗位消失 | 下架岗位会被自动清掉，正常；投递记录仍保留 |
| 想重投某条 | 删掉 `progress.json` 里该岗位 id 的记录（慎用） |
| 端口冲突 | 关掉占用 9222 的旧 Chrome 进程 |

## 依赖

- Python 3.10+，`pip install DrissionPage==4.1.1.4`
- 本机装有 Chrome（会复用你已有的登录 profile）
- Windows / macOS / Linux 均可，路径在 config 里改成对应系统的写法即可

## 风险与安全（务必读）

- 自动化操作违反 BOSS直聘用户协议的某些条款，**存在账号被限流/限制的风险**。本工具已做的防护：随机 18~45 秒拟人间隔、每日上限、只投 S/A 档、遇验证码停下等人。想更稳就把 `min_delay_s`/`max_delay_s` 调大、`daily_cap` 调小。
- 简历和账号都是你自己的：登录走你本人扫码，工具不收集、不上传任何数据，一切记录只存在你本机。
- 仅供个人求职使用，请勿用于批量营销或转售。
