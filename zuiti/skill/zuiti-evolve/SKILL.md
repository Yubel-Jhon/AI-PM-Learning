# zuiti-evolve · 自我进化（规则级学习回路）

## 为什么需要（一句话）

改写端回写人物卡，学的是"这个人"；"规则错了"却只有踩坑当场知道——脏字表 9/19 修过一次，
9/20 演示前又漏 tm/sb 才补齐，**同类坑踩两遍 = 经验没沉淀**。本 skill 把坑变成库，
让规则也走"实战 → 回写 → 下次先用"的同一条路。

## 三层机制（移植自 self-improving-agent，按嘴替现实裁剪）

| 层 | 原版做法 | 嘴替落地版 | 何时触发 |
|---|---|---|---|
| L1 实时反馈 | 每任务后 evaluate-task 打四维分 | 会话收尾四信号记经验（见下） | 每次改写/分析会话结束 |
| L2 周期反思 | optimize-agent 分析近 10 次评估生成计划 | "嘴替复盘"：聚类经验 + 读活数据 → 提规则修改案 | 用户喊复盘 / 同类经验 ≥2 条 |
| L3 跨副本共享 | sync-learning 拷 collective-wisdom 到各 workspace | 同步清单五步（见下），含桌面引擎 parity | 任何规则改动后必跑 |

裁剪说明：原版四份数据文件（evaluations/lessons/optimization-plan/performance-metrics）
合并成**一份经验库**——手动挡没有流水线，能落地的只有一条条教训本身；
评估结论直接写进 lesson 的 impact 字段，不为存而存。

## L1 会话收尾评估（轻量，别为记而记）

正常顺利的会话**不记**。出现以下任一信号才记：

- 用户**改了成稿再发**——改的方向就是规则的盲区（和人物卡「近期观察」的用户改稿信号并行，
  那条记的是"这个人"，这条记的是"规则"）
- 用户**没用 / 换了档位**——默认档判断错
- **触发重写/兜底**——质检层拦下了什么，说明上游规则有洞
- **SKILL.md 没覆盖的新场景**——当场的补丁记下来，复盘时扶正

记录格式（一行一条 JSON，追加进经验库）：

```json
{"id": "lesson-202609211430", "date": "2026-09-21",
 "category": "质检|规则|示例|分寸|引擎|同步 六选一",
 "lesson": "一句话说清坑和修法",
 "evidence": "脱敏现象，不含原话/人名",
 "impact": "high|mid|low", "applied": false}
```

**红线**：evidence 只写现象不贴原文——"成稿出现'尽快跟进'"可以写，原话和对方是谁不行。
经验库种子进仓库，运行数据在本地，人物卡内容两边都不许混进来。

## L2 周期复盘（触发词："嘴替复盘"）

1. **读经验库**：`applied=false` 的条目按 category 聚类，同类 ≥2 条就值得动规则
2. **读两份活数据**：各人物卡的「近期观察」段（改写端回写的实况）+ 本次没消化的新场景补丁
3. **出修改案**：每条 = 改哪个文件哪一节、改成什么、依据哪条经验。
   **列清单给用户确认，点头才动手**；一次最多改 3 条——改多了没法验证哪条起效
4. **动手后**：改过的经验标 `applied` + 日期；规则改动必跑 L3；
   涉及桌面引擎的（字数/脏字/禁语/降级），同步改 `zuiti_overlay.py` 对应表和逻辑，只改 skill 不算完

改写会话的评分参考（复盘时判断"哪类会话最常翻车"用，不做逐条流水）：
**总分 = 硬规则 30% + 原意保持 30% + 用户采纳 40%**（直接用=100 / 改了用=70 / 没用=0）。
原版四维（完成度/效率/质量/满意度）是给 Agent 干活打分的；嘴替的"任务"就是改写，
采纳率权重最高——质检全过用户也可能不用。某类场景均分 <70 → 该场景的示例/分寸优先复盘。

## L3 同步清单（规则改动后必跑，顺序固定）

1. `~/.claude/skills/<skill>/` —— Claude 本机生效版
2. `Desktop/嘴替-skill/skill/<skill>/` —— 分发版
3. 仓库 `AI-PM-Learning/zuiti/skill/<skill>/` —— 公开版（develop 分支）
4. 涉及输出规则（脏字/禁语/字数/元话语）→ 检查 `Desktop/嘴替-zuiti/script/zuiti_overlay.py`：
   `_CURSE_WORDS`（草稿火气，参与推档）与 `self._CURSE`+`_OUT_BANNED`（成稿 lint+兜底）
   **是两张表各管各的**，规则两边都要动——9/20 脏字表坑的根源就是只改了一张
5. diff 校验内容级一致：Windows 下三副本换行符 CRLF/LF 不齐会全文报假差异，
   `diff --strip-trailing-cr` 才是真差异

经验库跑法：种子文件在本目录 `lessons-learned.json`（新机器拷去本地路径起步）；
运行时追加写在 `Desktop/嘴替-zuiti/self-improvement/lessons-learned.json`
（工具目录本地文件，不进任何仓库）。

## 红线

- 经验库脱敏进仓库，原话/人名/聊天内容绝不进；运行库只在本地
- 复盘改规则必须用户点头；一次 ≤3 条，改完必跑 L3
- 经验也会过时：`applied` 后半年没再犯就移进文件末尾 archive 段，库保持能一眼读完
- 本 skill 只动"规则"，落点铁律沿用：**硬规则 > 人物卡 > 招式**，复盘不得越过硬规则改判断

## 与另外两个 skill 的关系（谁也不许只出不进）

- **zuiti-rewrite**：会话收尾按 L1 记经验（其「收尾评估」节指向本 skill）；
  复盘产出的新示例/新分寸回写进它的示例表和分寸表
- **chat-persona**：复盘时人物卡「近期观察」是输入之一；复盘若发现"分寸类"教训成体系
  （不是单个人特例），翻译回它的分寸表和 3do/3don't 写法
- 三条回路各管一层：人物卡学"这个人"，近期观察学"这一轮"，经验库学"规则本身"——
  都靠实战回写，都别只出不进
