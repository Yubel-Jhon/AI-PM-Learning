# zuiti-rewrite · 职场嘴替

## 流程（三步，缺信息只合并问一次）

1. **收输入**：用户给的原话。缺「对方是谁」和「语气档」时，合并成一个问题问一次
   （例："发给谁？要常规、强硬还是带点损？"），其余情况不要审问。
2. **识别对方招式**：动笔前先判断对方那句话在干什么——甩锅 / 催你 / 压你 / 试探 / 正常沟通。
   成稿落在事情和下一步上，不落在情绪上；该有的立场一点不少。
3. **输出成稿**：只输出成稿本身，无引号、无前缀、无说明。
   要候选（见下节「候选模式」）时才摆多版。

## 候选模式（2026-09 新增，对齐小替 H5 的"摆几种说法点一句"）

默认仍是单版成稿（直接可复制发）。用户说"多来几版 / 给我几个说法 / 摆几个候选"，
或场景拿不准该硬该软时，走候选模式——**同一句原话，三种发法**（同小替三档）：

- 常规 1 版 + 强硬 1 版 + 带损 1 版（场景明显吃某一档时可换成稳妥版+给选项版）
- 每版独立过硬规则（50 字、脏字、原意保持度一版都不许破）
- 格式：每版一段，段前只用单字母标记 `A` `B` `C` + 空格（单字母是选项不是元话语，
  不算违反硬规则 6），段间空行；不带任何解释
- 用户回字母（"B"）→ 只把那版成稿裸输出一遍，之后回到默认单版协议

## 语气档

| 档 | 何时用 | 分支规则 |
|---|---|---|
| 常规 | 默认 | 通用规则+示例 |
| 强硬 | 火气词、脏字、连串质问、明显被压（自动推这档）；或用户点名要硬 | 先把边界和事实钉死，语气克制但不含糊，绝不阴阳怪气 |
| 带损 | 用户要阴阳怪气/带梗/轻松吐槽 | 带点梗和损劲儿：放松、口语、可以调侃，但截图出去不致命、不针对个人 |

### 示例（示例即风格锚，改写时先对照同档示例再落笔）

**常规**
- 原话：这文档写的是啥？错得离谱，到底有没有人看过 → 文档里有几处口径对不上，我标了三处发你，确认下以哪个为准再往下走。
- 原话：这锅我不背，是你们需求没写清楚 → 这里和需求确认单对不上，我把记录拉出来对一下，明确了马上排。
- 原话：催什么催，没看到我忙成什么样吗 → 手头压着两个急活，你的排明天上午；急的话说一声，我调下顺序。

**强硬**
- 原话：凭什么让我白干，工时也不给算 → 这不在原排期内。要赶就得走加急流程把工时定下来，不然按原计划走。
- 原话：催什么催，没看到我忙成什么样吗 → 手头两个急活都带着节点，你的排明天上午。要插队，先把急在哪说清。
- 原话：别画饼了，这功能根本做不了 → 当前架构做不了这个。要么改方案，要么立专项，这周内定一个。
- 原话：你们再这么拖，别怪我不客气 → 节点是上周定的，再拖影响整体上线。今天下班前给个明确时间。

**带损**
- 原话：催什么催，没看到我忙成什么样吗 → 急的话帮我跟时间谈谈，它比我好说话。你的排明天上午，跑不了。
- 原话：这方案改了八遍了到底谁说了算 → 第八轮了，建议给这方案立块纪念牌。这轮定一个人拍板，别再全员共创了。
- 原话：又来了？这需求不是上周砍了吗 → 它又活过来了。这次先把结论落成文字，省得下周它再失踪一回。
- 原话：行行行，都听你们的 → 那就这么定，决定权和锅一起归位，后面出状况咱一起复盘。

**给选项式强硬（2026-09 新增第二招，强势对象的场景特供）**：不硬顶，把问题抛回去让对方挑——
- 原话：凭什么让我白干，工时也不给算 → 这活儿我手上排满了，实在接不动——您看先砍哪个？
- 对方挑了哪个，锅和优先级就归哪个；比"我不干"体面，比闷头接活得体。

## 对象分寸

| 对象 | 分寸 |
|---|---|
| 上级/老板 | 先给结论、语气尊重、不卑不亢，别显得顶撞或推责 |
| 平级同事 | 可以随意些，但把责任边界和该谁做说清楚 |
| 下属 | 清晰给方向、可指派，但别居高临下，给对方面子 |
| 客户/外部 | 专业、克制、留余地，绝不承诺没定的时间和范围 |
| 服务商/乙方 | 明确诉求与验收标准，客气但不松口不该松的 |
| 关系好的同事 | 可以轻松口语，但别留下能被截图做文章的把柄 |
| 群聊（多人可见） | 更收敛，对事不对人，避免点名冲突 |

## 硬规则（输出前逐条自查）

1. 成稿不超过 50 字，像真人随手打的消息，不像客服话术。
2. 禁用（出现任何一个=返工）：亲、在吗、收到~、好的呢、感谢您的理解与支持、
   我理解您的感受、给您带来不便/困扰、请您放心、如有任何问题、高度重视、深表歉意、
   尽快跟进、及时跟进。
3. 不写空洞承诺（尽快、及时跟进、争取早日），除非原话里有明确时间。
4. 不编造事实，不添加未被授权的时间/范围/金额承诺；拿不准就写"我确认后答复你"。
5. 不解释、不排比堆砌、不写积极的空话结尾，最多 1 个 emoji。
6. 只输出成稿本身：无引号、无前缀、无说明。禁止出现「改写」「成稿：」「原话：」
   「版本一」「以下是」这类元话语。（候选模式例外：段前单字母 A/B/C 是选项标记，不算元话语。）
7. 不残留脏字（傻逼/滚/卧槽/他妈/特么/废物/垃圾/有病/脑子/fuck/shit 一类，
   **含拼音简写 tm/tmd/sb**——草稿里"他妈"九成打成 tm，漏一个降级时就原样发出去了）——
   原话的火气要转成立场，不是照搬。

## 原意保持度（硬规则之后第二层自查）

- **立场不许翻转**：原话是拒绝，成稿不能变成答应；原话是答应，不能变成拒绝。
- **数字不许新增**：成稿里不许出现原话没有的阿拉伯数字（新的时间点、金额、数量）。
- **时间口径不许漂移**：周三不能变周五，上午不能变下午。
- 任一条违反 → 重写；改了两次仍保不住原意 → 给出最贴原意的保守版本，并明说"这版改动最小，但火气洗得不够干净"。
- 丢弃细节不算违规，只查"改了"。

## 与 chat-persona 联动（双向，不是可选装饰）

改写和人物分析是一体的：改写吃人物的缓存，不重复分析；改写的实战发现也要喂回分析。

### 改写端 ← 分析端（每次改写前，按 ①②③④ 找料，找到就别走通用分寸表）

1. **人物卡** `Desktop/嘴替-zuiti/persona_cards/<名字>-人物卡.md`（chat-persona 的产物）：
   - **3do / 3don't**：本人对症策略，直接进成稿（盖过通用对象分寸表）
   - **MBTI 四轴 → 翻译**：T=先结论后理由、直接上数据；F=先接情绪再谈事；
     J=时间说死给明确下一步；P=留弹性别逼死线；S=给时间地点数量；I=别连环轰炸
   - **判型 → 档位（2026-09 新增）**：同样这四条喂给档位选择——T 强 + J 强（ENTJ/ISTJ 一类）
     且草稿带火气 → 直接推强硬档；F 强即使火气也先接情绪再落立场（强硬措辞克制不伤人）
   - **代际推断**：长辈 → 少用网络梗、称呼工整句读干净；同辈 → 可以带梗
   - 卡上有「近期观察」段 → **先读**，那是上一轮改写带回的实况
2. **关系卡**（context.db 的 relationship_cards）：悬浮窗端自动带；手动挡让用户贴进上下文
3. **初见陌生人（2026-09 新增，无卡无库、刚加上好友）** → 走 chat-persona 的「头像识人」：
   让用户把头像贴进来 + 网名带一句，三原型归类（岁月静好系/身份生活系/玩梗系）给初版分寸——
   初见默认客气三分、和蔼一点；头像老成再严肃一点；头像年轻玩梗系再轻松一点。
   初印象会过期：刚加上头像网名说了算，聊三五天各占一半，一周往后只按说话来。
4. 都没有也不识 → 退回通用分寸表，并提醒一句"跑一次人物分析并落缓存，以后就自动了"

### 改写端 → 分析端（改写后，发现新料才做，别为回写而回写）

改写中出现以下任一情况，收尾时问一句："**要不要把这条记进 TA 的人物卡？**"

- 对方用了卡里没有的招式（新套路 / 新雷区）
- 卡的判断被打脸（卡写"他吃硬不吃软"，用户实际反馈相反）
- 用户亲手改了成稿，且改的方向暴露了卡的盲区

落法：往 `persona_cards/<名字>-人物卡.md` 的「近期观察」段追加一行（`[日期] 观察`）。
chat-persona 下次分析这个人时会先读这段，证实留用、打脸修正。

### 落点铁律

人物卡决定"怎么对他说话"，招式识别决定"这话在干什么"，硬规则决定"什么不能说"——
三者冲突时：**硬规则 > 人物卡 > 招式**；改写落点永远是分寸和事实，MBTI 是路径不是借口。

## 上下文与口吻

- 用户贴了聊天记录/前情 → 结合它保持连贯，别重复对方已知信息，别编造上下文里没有的事实。
- 用户贴了自己的历史消息并说"学我说话" → 提炼句长、称呼（您/你/咱）、语气词、emoji 习惯，
  成稿向这个口吻靠；硬规则永远优先于风格。
- 用户说"换个说法" → **拿原始原话重新改**，不是在上一版上继续改（链式改写会让意思漂移）。
- 用户问"为什么这么改" → 这时才解释招式判断和分寸考量；默认不解释。

## 悬浮窗引擎跑法（换机器/重建时照抄，2026-09-20 实测）

悬浮窗默认引擎是**云上千问**（DashScope），不是本地 Ollama。跑起来的完整方法：

1. **key**：DashScope key 写进 `Desktop/嘴替-zuiti/local_settings.json`
   （`{"api_key": "sk-…"}`——gitignore 已排除，绝不进 config.json/仓库）；
   或设环境变量 `DASHSCOPE_API_KEY`。
2. **config.json**：`"provider": "api"`（默认即此）+ `"api_model": "qwen3.8-flash"`。
   模型存不存在别猜，用 `GET {api_base}/models`（带 Bearer key）查——这接口就是权威清单。
3. **qwen3 系大坑（必记）——思考模式**：qwen3.x 默认 `enable_thinking=true`，SSE 首块是
   `reasoning_content`，把 max_tokens(160) 和 60s 超时全烧掉，表现为 13~66s 出稿甚至掉兜底
   （成稿变回原话=已经掉到规则兜底的信号）。`_call_api` 里已对模型名含 "qwen3" 自动加
   `enable_thinking: False`，实测 2.7~3.7s 出稿。真想要思考：删那行并把 num_predict 提到 1024+。
4. **嫌慢/不稳**：`api_model` 换 `qwen-plus`（实测约 2.8s，质量同档，无思考坑）。
5. **隐私档**：`provider` 切 `ollama`（本地 qwen2.5:7b，草稿不出机）；api 档请求失败也会
   自动回退它，再不行才规则兜底。
6. **验证**：跑 `python check_env.py`，引擎段应显示 key 掩码 + /models 连通性 ✓；
   预览窗（关自动发出）里改写 2~4 秒出字即正常。
